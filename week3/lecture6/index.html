    Week 3 — Lecture 2: SystemC Communication and TLM¶

    Course: Advanced Digital Design and Verification
    Instructor: Sneh Saurabh • Date: 28 Aug 2025
    Topic: SystemC Communication Primitives and Transaction-Level Modeling (TLM)

    1) Channels in SystemC¶

    Two types of channels:

    Feature Primitive Channels (sc_prim_channel) Hierarchical Channels (sc_channel/sc_module)
    Ports & hierarchy No Yes
    Contains processes No Yes
    Purpose Simple & fast communication Complex bus-like modeling (PCI, AMBA, etc.)
    Examples sc_fifo<T>, sc_mutex, sc_semaphore Hierarchical buses 
    graph TD
    Channels --> Primitive
    Channels --> Hierarchical
    Primitive --> sc_fifo
    Primitive --> sc_mutex
    Primitive --> sc_semaphore
    Hierarchical --> PCI
    Hierarchical --> AMBA

    2) Mutual Exclusion — sc_mutex¶

    • Provides exclusive access to shared resources.
    • Implements sc_mutex_if interface.
    • Member functions:
    • lock(): blocking acquire.
    • trylock(): non-blocking, returns 0 if locked.
    • unlock(): release.
    SC_MODULE(ChangeRoom) {
  sc_mutex door;
  void customer_1_change();
  void customer_2_change();
  void customer_3_change();
  SC_CTOR(ChangeRoom) {
    SC_THREAD(customer_1_change);
    SC_THREAD(customer_2_change);
    SC_THREAD(customer_3_change);
  }
};

    3) Resource Pooling — sc_semaphore¶

    • Allows multiple processes to share a limited number of resources.
    • Implements sc_semaphore_if interface.
    • Member functions:
    • wait(): blocking acquire.
    • trywait(): non-blocking.
    • post(): release one resource.
    • get_value(): available slots.
    SC_MODULE(Parking) {
  sc_semaphore slots;
  void car1();
  void car2();
  void car3();
  void car4();
  SC_CTOR(Parking) : slots(2) { // 2 slots available
    SC_THREAD(car1);
    SC_THREAD(car2);
    SC_THREAD(car3);
    SC_THREAD(car4);
  }
};

    4) FIFO Queues — sc_fifo<T>¶

    • First-in-first-out (FIFO) communication.
    • Implements sc_fifo_in_if<T> and sc_fifo_out_if<T>.
    • Member functions:
    • Writing: write(), nb_write(), data_write_event().
    • Reading: read(), nb_read(), data_read_event().
    • Query: num_available(), num_free().
    SC_MODULE(TicketCounter) {
  sc_fifo<int> customers;
  void add_new_customer();
  void process_customer();
  SC_CTOR(TicketCounter) : customers(3) { // queue size 3
    SC_THREAD(add_new_customer);
    SC_THREAD(process_customer);
  }
};

    5) Clock Channel — sc_clock¶

    • Derived from sc_signal.
    • Models periodic clock signals.
    • Constructor: sc_clock(name, period, time_unit, duty_cycle, start_time, pos_edge_first).
    sc_clock myclk("clk", 10, SC_NS, 0.5);

    6) Transaction-Level Models (TLM)¶

    Problem with HDL Models¶

    • RTL/HDL simulate every cycle and every signal change.
    • Too detailed for high-level exploration.
    • Slows down system-level verification.

    TLM Approach¶

    • Use function calls (transactions) instead of cycle-accurate signals.
    • 100–10,000x faster than RTL simulation.
    flowchart LR
  RTL1[RTL Model] -->|Pin & cycle accurate| RTL2[RTL Model]
  FM1[Functional Model] -->|Function call| FM2[Functional Model]

    7) TLM Applications¶

    • Firmware/software development before RTL is ready.
    • Architectural modeling.
    • Performance analysis.
    • Functional verification.
    graph TD
  TLM -->|fast| Software
  TLM -->|early| Architecture
  TLM -->|golden model| Verification

    8) Timing Styles in TLM¶

    • Loosely-timed (LT): whole transactions, fast, used in SW models.
    • Approximately-timed (AT): phase-based timing, more detailed.
    • Untimed (UT): no notion of time.
    Style Detail Level Use Case
    UT None Functional verification
    LT Transaction SW perf analysis, architecture
    AT Phase-based HW perf analysis, verification

    9) TLM-2.0 Overview¶

    • Standardized by OSCI in 2005 (1.0) and 2008 (2.0).
    • Mechanisms:
    • Sockets: communication endpoints.
    • Generic payload: standard data container.
    • Blocking / non-blocking transport.
    • Direct Memory Interface (DMI).
    • Quantum keeper for timed simulations.

    10) TLM Communication¶

    • Socket: endpoint for communication.
    • Initiator: creates and sends transactions.
    • Target: receives and processes transactions.
    sequenceDiagram
  participant Initiator
  participant Target
  Initiator->>Target: b_transport(payload)
  Target-->>Initiator: Response

    11) Initiators and Targets¶

    • Initiator socket: drives transactions.
    • Target socket: responds to transactions.
    • Interconnect can have many initiators and targets.
    graph LR
  I[Initiator] --payload--> T[Target]
  T --response--> I
