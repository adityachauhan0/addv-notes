    Week 2 — Lecture 1: SystemC¶

    Course: Advanced Digital Design and Verification
    Instructor: Sneh Saurabh • Date: 19 Aug 2025
    Topic: SystemC basics, toolchain, simulation kernel, processes, and data types

    Key Takeaways

    • SystemC = C++ library + discrete‑event kernel. You write C++ that models hardware structure & behavior with time.
    • Simulation phases: Elaboration → Execution (delta cycles & time) → Cleanup.
    • Modules contain ports, channels/signals, and processes (SC_METHOD, SC_THREAD, SC_CTHREAD).
    • Build with g++ (or MSVC/Clang), link libsystemc, ensure loader finds it (env LD_LIBRARY_PATH/DYLD_LIBRARY_PATH or rpath).
    • Numeric/logic families provide bit‑accurate arithmetic and four‑valued logic (0,1,X,Z). Use the closest type that satisfies semantics.
    • Time API: sc_time, wait(), events & notifications, time resolution and default unit control precision.

    1) What is SystemC?¶

    SystemC is a - C++ class library providing types (bit‑vectors, fixed‑point, events, clocks, channels) and macros (e.g., SC_MODULE). - An event‑driven kernel that schedules processes and advances time.

    classDiagram
  class Kernel {
    +delta_cycle
    +evaluate()
    +update()
    +next_event_time()
  }
  class SC_MODULE {
    +ports
    +channels
    +processes
  }
  class SC_METHOD
  class SC_THREAD
  class SC_CTHREAD
  Kernel <.. SC_METHOD : schedules
  Kernel <.. SC_THREAD : schedules
  Kernel <.. SC_CTHREAD : schedules
  SC_MODULE o-- SC_METHOD
  SC_MODULE o-- SC_THREAD
  SC_MODULE o-- SC_CTHREAD

    2) Hello World — minimal design¶

    2.1 Source (main.cpp)¶

    #include <systemc.h>

SC_MODULE(Hello_SystemC) {
  SC_CTOR(Hello_SystemC) { SC_THREAD(module_thread); }
  void module_thread() {
    SC_REPORT_INFO("Hello", "Module Thread Saying:: Hello SystemC World!");
  }
};

int sc_main(int argc, char* argv[]) {
  Hello_SystemC hello_i("hello_i");
  sc_start();
  return 0;
}

    2.2 Build & run (Linux, shared)¶

    # Compile
g++ -std=c++17 -I${SYSTEMC_HOME}/include -c main.cpp

# Link
g++ -L${SYSTEMC_HOME}/lib-linux64 -lsystemc -lpthread -o a.out main.o

# Loader (option A): env var
export LD_LIBRARY_PATH=${SYSTEMC_HOME}/lib-linux64:$LD_LIBRARY_PATH

# or (option B): bake rpath into executable
# g++ ... -Wl,-rpath,${SYSTEMC_HOME}/lib-linux64 -lsystemc -lpthread -o a.out

./a.out

    3) Simulation lifecycle & delta cycles¶

    sequenceDiagram
  participant K as Kernel
  participant P as Processes (ready)
  participant Q as Update Queue
  Note over K: t = 0, delta = 0
  K->>P: evaluate() (all sensitive/triggered)
  P-->>Q: request signal updates/events
  K->>Q: update() (commit signal writes)
  K-->>K: if more events in same time -> delta++ and repeat
  alt no more events at t
    K-->>K: advance time to next scheduled event
  end
    • Elaboration (C++ constructor time): build module hierarchy, bind ports↔channels, register processes, compute static sensitivities.
    • Execution: repeated evaluate → update → delta++ until no events remain, then jump to next time.
    • Cleanup: destruct objects, print reports.

    4) Processes & sensitivities¶

    4.1 Process matrix¶

    Process Can wait()? Typical use Sensitivity Notes
    SC_METHOD ❌ combinational sensitive << sig / next_trigger() runs to completion; default calls once at time 0 unless dont_initialize()
    SC_THREAD ✅ timed/stateful wait(evt) / wait(delay) coroutine; use loops; can wait(N, SC_NS)
    SC_CTHREAD ✅ (implicit clock) synchronous pipelines sensitive << clk.pos()/neg() via reset_signal_is() use wait() per cycle; reset style via reset_signal_is()

    4.2 Sensitivity rules¶

    • Static lists: declared at elaboration (SC_METHOD + sensitive << a << b;).
    • Dynamic: next_trigger(evt | delay) inside METHODS changes sensitivity for next invocation only.
    • dont_initialize() stops the first call at time 0.
    • SC_THREAD/SC_CTHREAD start suspended until first wait(...) completes.
    stateDiagram-v2
  [*] --> Sleeping
  Sleeping --> Ready: event or time triggers
  Ready --> Running: scheduled by kernel
  Running --> Sleeping: end of METHOD or `wait()` in THREAD

    5) Channels, ports, interfaces¶

    classDiagram
  class sc_interface { <<abstract>> +methods }
  class sc_port~IF~ { +bind(IF) }
  class sc_signal~T~ { +read() +write(T) }
  class sc_fifo~T~ { +read() +write(T) +num_available() }
  sc_signal ..|> sc_interface
  sc_fifo ..|> sc_interface
  sc_port o-- sc_interface

    Binding rules - One port binds to one interface (or a vector of ports binds one‑by‑one). - Directional convenience ports: sc_in<T>, sc_out<T>, sc_inout<T> wrap sc_port. - Multiple readers/writers: allowed by channel semantics (e.g., sc_signal allows 1 writer; multiple writers require a resolved channel).

    6) Time API¶

    • sc_time t(10, SC_NS);
    • wait(10, SC_NS), wait(evt), wait(evt | t).
    • Global configuration: 
      sc_set_time_resolution(1, SC_PS);
sc_set_default_time_unit(1, SC_NS);

    sequenceDiagram
  participant T as SC_THREAD
  participant K as Kernel
  T->>K: wait(5, SC_NS)
  K-->>T: resume at t0+5ns
  T->>K: evt.notify(10, SC_NS)
  T->>K: wait(evt)
  K-->>T: resume when event fires

    Event notification - Immediate: notify() (next delta). - Timed: notify(dt) schedules in future time.

    7) Data types (namespace sc_dt)¶

    flowchart LR
  DT[Types] --> L[Logic]
  DT --> N[Numeric]
  L --> L1[sc_logic (0,1,Z,X)]
  L --> L2[sc_bv<W> 2‑valued]
  L --> L3[sc_lv<W> 4‑valued]
  N --> I1[sc_int<W>]
  N --> I2[sc_uint<W>]
  N --> I3[sc_bigint<W>]
  N --> I4[sc_biguint<W>]
  N --> F1[sc_fixed<W,I> / sc_ufixed<W,I>]
  N --> F2[sc_fix / sc_ufix]
  N --> FF[sc_fix_fast / sc_ufix_fast]

    Selections & concatenation 

    sc_uint<4> a = 0xA;         // 1010
sc_uint<4> b = 0x3;         // 0011
sc_uint<8> cat = (a, b);    // 1010_0011

sc_uint<4> y = 0;
y.range(3,1) = 0b111;       // y = 1110
bool b0 = (y[0] == 0);

    Fixed‑point essentials 

    sc_fixed<5,3>  weight = 1.5;   // W=5, I=3 (signed)
sc_ufixed<8,6> price  = 12.25; // W=8, I=6 (unsigned)

// Runtime‑configurable
sc_fix  bias(5,3);             // W=5, I=3
sc_ufix dist(8,2);

    Quantization / Overflow (when using full fixed‑point types) - Quantization modes: SC_TRN, SC_TRN_ZERO, SC_RND, SC_RND_ZERO, SC_RND_MIN_INF, SC_RND_INF, SC_RND_CONV. - Overflow modes: SC_WRAP, SC_WRAP_SM, SC_SAT, SC_SAT_ZERO, SC_SAT_SYM.

    Performance

    SystemC types are implemented as classes; arithmetic is slower than native C++. Use the narrowest accurate type, and prefer sc_uint/sc_int over big/fixed types unless required.

    8) Tracing & reporting¶

    sc_trace_file* tf = sc_create_vcd_trace_file("wave");
sc_trace(tf, clk, "clk");
sc_trace(tf, d.cnt, "cnt");
sc_start(200, SC_NS);
sc_close_vcd_trace_file(tf);
    • SC_REPORT_INFO/WARNING/ERROR/FATAL with categories; filter via sc_report_handler.
    • VCD grows fast; trace only what you inspect.

    9) Build systems (beyond one‑liners)¶

    CMake 

    cmake_minimum_required(VERSION 3.16)
project(hello_systemc CXX)
set(CMAKE_CXX_STANDARD 17)
set(SYSTEMC_HOME $ENV{SYSTEMC_HOME})
include_directories(${SYSTEMC_HOME}/include)
link_directories(${SYSTEMC_HOME}/lib-linux64)
add_executable(hello main.cpp)
target_link_libraries(hello systemc pthread)
# rpath so you don't need LD_LIBRARY_PATH
set_target_properties(hello PROPERTIES INSTALL_RPATH "${SYSTEMC_HOME}/lib-linux64")

    Windows notes - Use MSVC or MSYS2/Clang. Link systemc.lib; the runtime DLL must be on PATH. - Replace -lpthread with appropriate Windows threading lib (SystemC for Windows usually bundles it).

    10) Common pitfalls & fixes¶

    Symptom Root cause Fix
    error while loading shared libraries: libsystemc.so Loader can’t see shared lib Set LD_LIBRARY_PATH or use linker rpath
    Undefined refs to sc_* Forgot -lsystemc or wrong -L Add correct -L dir and -lsystemc -lpthread
    ABI mismatch SystemC built with different compiler/flags Rebuild SystemC or match toolchain
    Multiple writers to sc_signal Channel semantics violated Use resolved channel or arbitration
    SC_METHOD using wait() Illegal in methods Convert to SC_THREAD or use next_trigger()

    11) Mini testbench skeleton¶

    SC_MODULE(tb) {
  sc_clock clk{"clk", 10, SC_NS};
  sc_signal<bool> rst;
  DUT* dut{nullptr};
  SC_CTOR(tb) {
    dut = new DUT("dut");
    dut->clk(clk);
    SC_THREAD(stim);  // drive reset, inputs
  }
  void stim(){
    rst = 1; wait(2, SC_NS); rst = 0; // etc.
    wait(1, SC_US);
    sc_stop();
  }
};
